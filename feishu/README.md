# 飞书妙搭定时推送配置指南

本目录用于在**飞书妙搭（低代码平台）** 中搭建「会议论坛信息定时推送」插件。妙搭为可视化配置，本指南给出完整流程与关键配置值（Feed URL、表结构、自动化逻辑、卡片模板）。

## 0. 前置条件

- 拥有飞书企业租户，并具备**妙搭应用**的创建/发布权限。
- 数据 Feed 已公开可访问（GitHub Pages 发布后）：
  - 活动 Feed：`https://Logicar.github.io/Event-Aggregator/data/events.json`
  - 归档 Feed：`https://Logicar.github.io/Event-Aggregator/data/archive.json`

## 1. 创建妙搭应用

1. 进入飞书妙搭，新建应用（或新建多维表格 + 自动化）。
2. 命名如「会议论坛信息推送」。

## 2. 创建多维表格（Base）

新建一张多维表格，字段按下表配置（详见 [table-schema.md](table-schema.md)）：

| 关键字段 | 类型 | 说明 |
|---|---|---|
| `id` | 文本 | **设为唯一字段**，用于去重/增量 |
| `title` | 文本 | 活动标题 |
| `start_date` / `end_date` | 日期 | 举办起止 |
| `province` / `city` / `venue` | 文本 | 地点 |
| `registration_url` | 链接 | 报名入口 |
| `registration_deadline` | 日期 | 报名截止 |
| `registration_requirements` | 文本 | 报名条件（换行多条） |
| `url` | 链接 | 详情页 |
| `source_name` / `source_type` | 文本 / 单选 | 来源 |

## 3. 创建自动化流程（核心）

新建一条自动化，步骤依次为：

### 步骤 1 — 定时触发器
- 类型：**定时触发**
- 频率：每日；建议**工作日 09:00**（或按需每天）。

### 步骤 2 — HTTP 请求（拉取 Feed）
- 动作：**调用外部接口 / HTTP 请求**
- 方法：`GET`
- URL：`https://Logicar.github.io/Event-Aggregator/data/events.json`
- 解析响应体中的 `events` 数组。

### 步骤 3 — 循环处理每条活动
- 动作：**循环**（遍历 `events`）。

### 步骤 4 — 按 id 查找记录（去重）
- 动作：**查找记录**（多维表格）
- 条件：`id` 等于当前循环项的 `id`。

### 步骤 5 — 条件分支
- **若不存在该 id**：
  - 动作 A：**新增记录**，写入当前活动字段。
  - 动作 B：**发送飞书消息**（卡片模板见 [card-template.json](card-template.json)），推送给目标群/员工。
- **若已存在该 id**：
  - 动作 C：**更新记录**（同步最新字段，但不重复推送）。

> 效果：仅「首次发现」的活动触发推送，避免重复打扰。

## 4. 推送目标

- 群聊：选择目标群（可建「会议信息」内部群）。
- 个人：选择指定员工（如科研管理/行政负责人）。
- 卡片消息含「报名链接」与「详情页」按钮，员工点击直达。

## 5. 验证

1. 用测试群跑通一次：确认收到卡片、字段正确（时间/地点/报名链接/截止）。
2. 连续两日运行：确认**无重复推送**、增量正确。
3. 发布到正式群。

## 6. 归档资料说明

已结束活动在 `archive.json` 中，**不进入每日推送**。如需在飞书内查阅历史活动资料，可另行建一张「归档」多维表格，按相同方式从 `archive.json` 同步（字段含 `materials`），或直接引导员工访问网页端「已结束·资料回放」视图。
